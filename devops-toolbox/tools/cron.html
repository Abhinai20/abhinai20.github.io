Cron syntax reference

A standard crontab line has five time fields followed by the command to run. Each field accepts a single value, a list, a range, or a step.

  • minute — 0–59
  • hour — 0–23, on a 24-hour clock
  • day-of-month — 1–31
  • month — 1–12, or JAN–DEC
  • day-of-week — 0–7, or SUN–SAT. Both 0 and 7 mean Sunday.

Special characters

  • * — every value in the field.
  • , — a list, as in 1,15,30.
  • - — an inclusive range, as in 9-17.
  • / — a step. */15 in the minute field means every 15 minutes. A step can follow a range too: 0-30/10 runs at 0, 10, 20 and 30 only.

Shorthand aliases

Most cron implementations accept these in place of all five fields: @yearly (equivalent to 0 0 1 1 *), @monthly, @weekly, @daily, @hourly, and @reboot.

Common expressions

  • */5 * * * * — every five minutes.
  • 0 * * * * — once an hour, on the hour.
  • 30 2 * * * — every day at 02:30.
  • 0 9 * * 1-5 — 09:00 on weekdays only.
  • 0 0 1 * * — midnight on the first of each month.
  • 15 3 * * 0 — 03:15 every Sunday.

Gotchas worth knowing

Day-of-month and day-of-week are OR'd, not AND'd

This is the single most misunderstood part of cron. When both the day-of-month and day-of-week fields are restricted — neither is * — the job runs when either matches, not when both do.

So 0 0 13 * 5 does not mean "Friday the 13th". It means midnight on the 13th of every month, and also midnight every Friday. If you want a job to run only on a weekday that is also a particular date, you have to test for it inside the command itself rather than in the schedule.

Cron runs with a minimal environment

A cron job does not inherit your interactive shell's environment. PATH is typically just /usr/bin:/bin, and your profile scripts are never sourced. A command that works when you paste it into a terminal can fail under cron purely because a binary is not on that reduced path. Use absolute paths, or set PATH explicitly at the top of the crontab.

Percent signs must be escaped

In a crontab, an unescaped % is translated into a newline, and everything after the first one is fed to the command as standard input. This bites anyone using date format strings. Write \%Y\%m\%d, or move the command into a script.

Daylight saving time can skip or repeat a job

Cron schedules in the system's local timezone. When clocks jump forward, a job scheduled inside the skipped hour may not run at all that day; when they fall back, a job in the repeated hour can run twice. For anything where exactly-once matters, run the machine's cron in UTC, or make the job idempotent so a second run is harmless.

@reboot means daemon start, not boot

It fires when the cron daemon itself starts, which usually coincides with boot but is not the same event. Restarting cron re-triggers it. It is also not a substitute for a service manager — if the job needs to run reliably and be restarted on failure, a systemd unit is the better tool.

Six fields means something else

If an expression has six fields rather than five, it is probably not Unix crontab. Spring's scheduler and several container platforms put seconds first; Quartz uses a sixth field for the year and supports ?, L and W that standard cron does not. Checking the field count first saves a lot of confusion.
