kubectl JSONPath syntax

JSONPath lets you pull specific fields out of kubectl output instead of parsing it with text tools. The basics:

  • {.items[*].metadata.name} — the name of every item.
  • {.items[0].spec.containers[*].image} — every image in the first item.
  • {range .items[*]}{.metadata.name}{"\t"}{.status.phase}{"\n"}{end} — iterate and format.
  • {.items[?(@.status.phase=="Running")].metadata.name} — filter on a field.
  • {.metadata.annotations['kubernetes\.io/description']} — a key containing a dot must be escaped.

Use it as kubectl get pods -o jsonpath='...'. The surrounding single quotes keep the shell out of it.

Gotchas worth knowing

kubectl's JSONPath is not standard JSONPath

It is a Go implementation with its own dialect. $ is optional, range/end exist and are not in the original spec, and several filter and script expressions from other JSONPath libraries are unsupported. An expression copied from a general JSONPath tester frequently fails here, and vice versa.

Dots in keys must be escaped

Kubernetes labels and annotations are full of keys like app.kubernetes.io/name, and a bare dot is a path separator. Use bracket notation with escaped dots: {.metadata.labels['app\.kubernetes\.io/name']}. Forgetting this returns nothing rather than an error, which makes it look like the field is missing.

No output usually means no match, not an error

A path that does not exist produces an empty result silently. In a script that is indistinguishable from a legitimately empty value, so a typo becomes a silent wrong answer. When a query returns nothing unexpectedly, check the raw object with -o json before assuming the resource is absent.

Output is unseparated by default

{.items[*].metadata.name} joins names with spaces and no trailing newline, which makes the result awkward to loop over. The range form with explicit {"\n"} is almost always what you want in a script.

Quoting breaks on Windows

The single quotes that protect the expression in bash are not quotes in cmd.exe, and PowerShell interprets the contents differently again. On Windows, swap to double quotes and escape the inner ones, or put the expression in a file and reference it.

Consider -o custom-columns instead

For the common case of "show me these three fields as a table", custom-columns is shorter and more readable than the equivalent range expression: -o custom-columns=NAME:.metadata.name,PHASE:.status.phase. Reach for JSONPath when you need filtering or a format custom-columns cannot express.
