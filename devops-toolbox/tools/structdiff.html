Config Diff (JSON / YAML)

A line-based diff is a one-liner. A structural diff is not: this ignores key order and formatting and reports the exact paths that differ — which is what you want when comparing two manifests or two values.yaml files.

Paste both sides and click "Compare".

Why a structural diff beats a text diff

A line-based diff compares characters, so it reports differences that do not exist and misses ones that do. Reformatting a file, reordering keys, or changing indentation produces a wall of changes with no semantic content — while a genuine change buried in a reformatted block is easy to miss entirely.

A structural diff parses both documents first and compares the resulting data, so key order and whitespace stop mattering and what you see is what actually changed.

Gotchas worth knowing

Object key order is meaningless, array order is not

Two objects with the same pairs in a different order are equal. Two arrays with the same elements in a different order are not — and sometimes the order genuinely matters, as with nginx location blocks, IAM statement evaluation, or an ordered pipeline. A tool that normalises array order will hide real differences; one that does not will report noise when the order is irrelevant. Know which case you are in.

Type changes hide inside equal-looking values

"8080" and 8080 render identically in a terminal and behave differently in code. The same applies to "true" versus true, and to a null that became an empty string. These are exactly the changes a text diff cannot flag and that cause configuration bugs.

Absent is not the same as null or empty

A missing key, a key set to null, and a key set to an empty string are three different states, and they often behave differently — a missing field may take a default while an explicit null overrides it. A diff that collapses them will report "no change" across a meaningful one.

Numeric precision drifts through parsers

Round-tripping through a JSON parser can turn 1.0 into 1, or lose precision on integers beyond 2^53. The difference reported may therefore be an artefact of parsing rather than a change in the source file.

Comments disappear

Parsing YAML to compare it discards comments, so a change that only edits a comment shows as no change at all. If the comment carries operational meaning — and in configuration it often does — a structural diff is the wrong tool for reviewing it.

Diffing rendered output, not templates

For Helm or Kustomize, comparing the templates tells you little; comparing the rendered manifests tells you what will actually be applied. Rendering both sides first and diffing the output is how you catch a values change that silently altered something three levels down.
