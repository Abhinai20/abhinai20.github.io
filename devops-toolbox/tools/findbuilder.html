How find is structured

A find command reads as find [where] [tests] [action] — the starting path, then conditions, then what to do with matches. Everything after the path is evaluated left to right, which matters more than it first appears.

  • -name '*.log' — match the filename; -iname ignores case. Quote the pattern so the shell does not expand it first.
  • -type f / -type d / -type l — regular files, directories, symlinks.
  • -mtime +7 — modified more than seven days ago; -mmin -30 is the same idea in minutes.
  • -size +100M — larger than 100 megabytes.
  • -maxdepth 1 — do not descend. Place it before other tests.
  • -exec cmd {} + — run a command on the matches.

Gotchas worth knowing

-exec ... + beats -exec ... \;

The semicolon form runs the command once per file, which on a large tree means thousands of process spawns. The + form batches as many paths as fit onto one command line, exactly as xargs would, and is usually an order of magnitude faster. Use \; only when the command genuinely takes one argument at a time.

Unquoted patterns are expanded by the shell

find . -name *.log lets the shell expand *.log against the current directory before find ever sees it, so the command either searches for one specific filename or fails with "paths must precede expression". Always write -name '*.log'.

-delete is not a safe thing to append

It deletes immediately, with no confirmation and no undo, and it is easy to get wrong in ways that are catastrophic rather than merely annoying. Run the command with -print first and read the list, then swap in -delete. Note too that -delete implies -depth, which can change how it interacts with -prune.

Filenames can contain spaces and newlines

Piping find into xargs breaks on any path containing whitespace, which is how a cleanup script ends up deleting the wrong thing. Use -print0 with xargs -0, or avoid the pipe entirely with -exec ... +.

-mtime counts whole 24-hour periods

-mtime +1 does not mean "since yesterday" — it means at least two full days old, because the fractional part is discarded. For anything where the boundary matters, use -mmin or compare against a reference file with -newermt '2026-01-01'.

Order of tests changes the result and the cost

Conditions short-circuit, so putting the cheap, selective test first avoids running an expensive one on every file. It also changes semantics with -prune: pruning has to come before the thing it is meant to exclude, or you will have already descended into the directory you were trying to skip.

GNU and BSD find differ

macOS ships BSD find, which wants -type f before some options that GNU accepts anywhere, handles -regex differently, and lacks a few GNU extensions. A script written on Linux is worth testing on macOS before you rely on it in a shared repository.
